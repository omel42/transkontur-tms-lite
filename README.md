# ТрансКонтур — цифровая логистическая компания

Интерактивный MVP экосистемы для экспедитора: публичный сайт приводит заявку, логист ведёт её до рейса, а клиент, перевозчик и водитель получают отдельные простые интерфейсы.

## Посмотреть

- публичный сайт: <https://omel42.github.io/transkontur-tms-lite/>
- кабинет логиста: <https://omel42.github.io/transkontur-tms-lite/#office>
- ссылка для клиента: <https://omel42.github.io/transkontur-tms-lite/#track/TK-24031>
- кабинет перевозчика: <https://omel42.github.io/transkontur-tms-lite/#carrier/TK-24031>
- мобильный экран водителя: <https://omel42.github.io/transkontur-tms-lite/#driver/TK-24031>

## Что уже работает в прототипе

- создание заявки с сайта и из кабинета во время телефонного разговора;
- канбан заявок: новый контакт → уточнение → расчёт → согласование;
- превращение согласованной заявки в рейс;
- маршруты, экипаж, ETA, статусы, хронология и контрольные точки;
- стоимость клиенту, себестоимость, маржа, дебиторка и выгрузка CSV;
- чек-лист заявки, ТрН, закрывающих документов и счёта;
- гостевые ссылки для клиента, перевозчика и водителя;
- адаптивный интерфейс, PWA-манифест и автономный кэш;
- локальное хранение данных без сервера.

## Граница MVP

Это проверяемый интерфейсный прототип, а не готовая производственная TMS. Здесь намеренно нет серверной базы, реальной авторизации, электронной подписи, фоновой геолокации, отправки уведомлений, интеграции с 1С и оператором ИС ЭПД.

Следующий этап после проверки с логистом: PostgreSQL, ролевой доступ, журнал действий, защищённые ссылки, резервное копирование и выбранные интеграции. Нейросеть не нужна, пока не найден повторяющийся ручной сценарий с измеримой экономией времени.
